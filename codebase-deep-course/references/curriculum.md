# 编排顺序

## 全局：建立可运行的整体，再拆开理解

| 顺序 | 学习问题 | 产物 |
|---|---|---|
| 全貌 | 用户做一个动作，系统如何接住？ | 两条主链、组件与职责 |
| 首次成功 | 怎样证明服务和最小业务能跑？ | 可重复结果、环境检查 |
| 输入准备 | 原始输入怎样变成可处理的数据？ | 带来源的结构化记录 |
| 表示与存储 | 怎样持久化、关联、计算和索引？ | ID、版本、存储与查询 |
| 请求执行 | 新请求怎样找到数据？ | 候选、过滤、融合与排序 |
| 结果形成 | 中间数据怎样成为用户结果？ | 上下文、返回、引用、错误 |
| 增强机制 | 基础方案哪里不足，如何改善？ | 增强路径与失效边界 |
| 复现评测 | 能否从头实现并验证改进？ | 实验、对照与指标 |
| 运行观测 | 这一轮实际执行了什么？ | 调用树、ID、耗时与诊断 |

这是教学依赖模板，不要求每个项目九章。编译器可替换为词法、语法、中间表示、优化、执行；电商可替换为订单、支付、库存、履约。保留“全貌、首次成功、数据和执行、验证”的学习关系。

部署章先获得最小成功，不提前塞入所有原理。增强机制在基础链路之后讲，读者才有比较基线。观测用于最后把静态设计映射到真实运行；之前各章仍需自己的输出与日志检查。

## WeKnora / RAG 参考路线

1. **全貌**：上传与问答、职责、ID、异步状态、检索与完整 QA 的不同入口。
2. **Windows 搭建**：Docker/WSL、模型角色、网络与卷、健康检查、首次引用。
3. **解析分块**：类型与路由、OCR 边界、清洗、Unicode、重叠、父子块、来源。
4. **向量入库**：Embedding 协议、维度和签名、距离、批量、幂等、索引与原文回查。
5. **查询召回**：历史与改写、查询向量、BM25、RRF、去重、阈值、候选变化。
6. **重排生成**：独立重排协议、失败降级、合并、父块扩展、上下文预算、实际 messages、引用、流结束。
7. **Neo4j**：身份与约束、Cypher、实体关系抽取、匹配、邻接扩展、证据回查、噪声、组价迁移边界。
8. **双语言评测**：完整 CLI、同协议、固定数据、正常和失败、四策略对照、指标单位、迁移缺口。
9. **Langfuse**：Trace/Span/Generation/Session、已有埋点、部署与端点、异步传播、流计时、双语言练习与排障。

Neo4j、Milvus、pgvector 必需是原用户的指定，不是新项目默认。图谱跳数、解析主路径和 trace 名称都要重新核对当前版本。

## 一章内部的默认路线

1. **问题与目标**：学完能做什么，前章哪个产物进入本章。
2. **小节导航与流程图**：阅读路线与可回查位置。
3. **机制概览**：必要概念以及它解决的缺口。
4. **输入输出契约**：字段、来源、身份与实例。
5. **逐步执行**：同一对象的数据变化，穿插手算或交互。
6. **边界与失败**：2–3 个常见失败及原因。
7. **操作与判读**：命令、预期输出、下一步检查。
8. **真实源码精读**：入口、调用、条件与配置选择。
9. **完整教学函数及语言对照**：全部步骤怎样连接并实际运行。
10. **应用题与衔接**：复述产物并说明它怎样进入下一章。

可将操作、源码放在对应机制旁边，不强迫先读完所有理论。高级细节可折叠，主因果链保持可读。

## 为什么这样编排

先看用户结果，名词才有用途；先跑最小链，理论才有观察对象；先看数据，参数才不是抽象名字；先基础后增强，取舍才有基线；最后评测和观测，从“能跑”进展到“知道为什么这样跑”。

## 贯穿案例

选一个依赖 2–3 份资料或业务对象的问题，每份只提供部分证据；增加名称相近但版本不适用的干扰项、确实无证据的问题。各章复用稳定 ID。

虚构清单 A、定额 A、材料 M、规则 R 可贯穿：源文档采用关系 → 版本和单位 → 图谱来源 chunk → 检索候选 → 答案出处。不要将示意名称写成真实行业规范。

## 增补章节

确定前置依赖后再选择插入或追加；同时更新章节数据、上下章、小节锚点、进度分母、恢复阅读、打印和验证记录。优先稳定章节 ID；中间插章时迁移旧 ID 映射，不能因数组序号变化错配已学记录。
