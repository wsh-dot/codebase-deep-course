# 源码证据与可运行实验

## 从行为找入口

先读路由、CLI 命令、队列消费者及配置，追踪 handler → service → repository/adapter → 外部服务。事件驱动系统还要连接“登记事件”和“执行处理器”；只有事件名字不能证明内部行为。

证据表每行包括业务动作、入口文件/函数、下游调用、输入输出类型、配置条件、同步/异步边界、失败传播和源位置。不能只列文件名。搜索优先使用可用的快速文本搜索工具，顺序阅读目标函数周边确认上下文。

记录完整提交号和工作区变化。源码链接使用固定提交；镜像标签与构建来源单独记录，`latest` 不代表该源码。新 SDK/API 写法查官方文档并记录版本和核对时间；本例中的版本只作为历史资料。

## 四类内容和测试状态是两个维度

| 内容身份 | 允许的表述 | 不应混淆 |
|---|---|---|
| 源码事实 | 当前函数在条件 X 下调用 Y | 静态分析不能证明服务实际运行 |
| 教学简化 | 省略队列的串行教学实现 | 不能声称产品默认也是串行 |
| 模拟演示 | 固定向量、固定答案、设定耗时 | 不能充当真实效果与延迟 |
| 扩展设计 | 建议增加多跳/新数据库 span | 不能写成当前功能 |

每类另标已实测或未实测，以及测试层级。例如真实 SDK 向本地接收器导出通过，只证明编码、父子关系与传输；没有证明 Langfuse 认证、存储、后台处理与界面展示。

## 摘录与完整函数

正文中的产品源码摘录应是连续原文，不插入省略号、不更名、不调整逻辑；解释放在代码外。过长函数拆成标注起止行的连续片段，并保留完整源码入口。

构建器根据文件和唯一标记或解析定位提取；多个匹配时停止并修正定位，不直接选第一处。提取后记录路径、起止行、片段 SHA-256、提交。若当前文件有变化，固定提交链接可能不再一致，要标注工作区版本或读取提交中的原文。

在 HTML 中可使用本 Skill 审计脚本的协议：

```html
<code data-source-path="src/example.py" data-start="12"
      data-sha256="片段UTF-8的SHA-256">经过HTML转义的原始片段</code>
```

哈希文本统一 LF 换行，不含构建器擅自添加的末尾换行。只记录片段哈希不能证明语义正确；仍需人工核对解释、条件与版本。

### 确定性提取与严格审计

以下使用 Python 3.9+ 和 Git；替换路径、标记和范围后运行。标记按行内子串匹配，起点必须在全文恰好命中一次；结束标记也必须唯一，且包含结束行。也可用 `--lines N` 指定连续行数，超出文件会失败。

```text
python <skill-dir>/scripts/extract_source.py --repo <repo-root> --path src/example.py --revision <commit> --start-marker "def build_context(" --lines 12 --output evidence/context.json --html-output evidence/context.html
python <skill-dir>/scripts/audit_course.py <course.html> --repo <repo-root> --offline --require-revision --output evidence/audit.json
```

将 JSON 的 `html` 字段或生成的 HTML 片段原样加入课程。产物记录完整提交号、文件路径、起止行、片段与文件哈希；审计从该提交重新读 blob，不因本地工作区修改而误报，也不让变更冒充提交内容。默认读取 HEAD 提交，不隐式读取当前文件。

教学代码尚未提交时显式使用 `--worktree` 替代 `--revision`。此时 `revision=null`，另记可用的 `base_revision` 和是否不同于基准；审计核对当前文件及文件哈希。非 Git 文件夹或未跟踪文件不能伪造提交号。Git 基准获取失败时基准记为空，正文应说明来源限制。

零匹配、多匹配、无效范围、越界路径、无效提交、非 UTF-8 源码都应失败，修正定位或来源后再生成；不要手补虚构行号。用 `--require-revision` 拒绝旧的无版本摘录。源码课程不能通过 `--allow-no-source` 绕过缺失证据；概念教程可显式使用，但报告仍标明源码未核验。

### 技能包发布

```text
python <skill-dir>/scripts/package_skill.py <skill-dir> <outside-dir>/codebase-deep-course.zip
python -m unittest discover -s <skill-dir>/scripts -p "test_*.py"
```

打包器对所有已识别文本格式（包括 YAML）严格 UTF-8 解码，拒绝 GBK 等文本；不打包缓存和依赖目录。全部校验通过后才替换最终 ZIP，并核对解压字节与 SHA-256。新添文本扩展名时加入 `TEXT_SUFFIXES`，不要将未知格式自动声称已验编码。主 Skill 与元数据也需按宿主环境的格式校验器检查。

## 流程图也是可审查证据

节点表示真实动作/分支/边界，包含简短名称与输入输出；详情里放函数位置和原文。边区分调用、数据传递、入队、异步消费、流式返回；条件写在边上。失败/降级与普通路径使用不同标识，不能仅靠颜色。

先画总体图，再拆入口、入库、解析、检索、生成、图谱、实验等局部图。控制单图密度，避免一张“完整图”挤满所有函数。节点点击读源码的交互要有键盘路径和静态后备。

已有源码导读正文保留，图作为补充。图说明“可能执行”，运行 trace 说明“这次观测到执行”，两者不等价。

## 双语言不是双份伪代码

仅在用户要求双语言时提供两套独立项目。统一数据协议、CLI 参数含义、环境变量、固定资料、评测问题、排序规则和失败语义；各自依赖文件与输出目录独立。

跨语言要特别检查：Unicode 码点与 UTF-16 长度；浮点比较；稳定排序及相同分数的 tie-break；哈希编码/字段顺序；空值与布尔值；异步调用是否 await；错误是否被吞掉。不要把实现本身当测试的唯一预期，应有独立手算样例和行为不变量。

资料协议至少包含 document/source、page/offset、chunk ID、文本、版本和命名空间；候选包含来源通道、分数类型、排名；引用能回查实际原文。项目不需要的字段可删，但要说明取舍。

生成、Embedding、Rerank 使用独立配置。重排协议需按服务明确适配，不能假定所有模型都是 OpenAI chat 格式。使用直接 HTTP 有利于学习请求过程，但实际项目已有框架时要解释框架边界，不强行重写产品。

## 运行模式分层

- **无凭据演示**：固定数据与结果，清楚标注模拟；用于教学和一致性验证。
- **真实存储 + 固定模型**：验证数据库协议、幂等、查询和身份关联。
- **真实存储 + 真实模型**：验证实际效果、模型协议、延迟与用量。

模式名可调整；输出必须能辨识模式。不能因为固定数据结果好就断言真实模型检索准确。用户指定三库必需时，真实模式不能静默退回内存；缺服务要报清晰错误。

至少验证正常入库问答、重复入库、维度不匹配、候选去重、重排失败、无证据、版本与命名空间隔离。复杂输入如扫描 PDF/Office 的全套解析可通过产品实操覆盖，但应写清精简实验支持范围。

## 指标与观测

对照组先固定问题、证据标注、资料版本、后端、模型和参数；每次改一个因素。RAG 可比较向量、混合、加重排、加图谱四组，其他项目换成对应基线。

Recall@K 明确按文件还是 chunk、分母是什么、K 是候选数还是最终上下文数；MRR 明确什么算相关；证据支持用人工或已说明的评审方法，不靠“出现引用编号”。报告退化样例与延迟，不只展示成功案例。

观测章节说明 trace/span/session/业务 ID、上下文传播、异步任务、重试、流结束与 flush。父耗时包含子耗时，并行子步骤不能直接累加。没有 usage 就标记缺失，不能把未知成本填成零。未埋点的数据库查询不会自动出现在树上；不可恢复模型没有返回的内部推理。
