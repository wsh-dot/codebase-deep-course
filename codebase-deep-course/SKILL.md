# 源码深度课程编写

让学习者能够独立解释、运行、排障和迁移设计，而不只是认识组件名称。默认读者懂一些编程但不熟悉该系统；用户指定的基础、语言、必需组件和交付形式优先。

本 Skill 提炼自 WeKnora 深度课程，适用于其他仓库。它自包含，不依赖特定模型、Codex 工具、Archify 安装或原 WeKnora 文件。示例中的技术选型、提交号、章节数和未实测状态不能移植成新项目事实。

## 参考资料路由

- 完整创作：先读 [教学写法](references/pedagogy.md) 和 [编排顺序](references/curriculum.md)。这是核心要求，不可只按标题猜内容。
- 源码与实验工作：读 [证据与实验](references/source-and-labs.md)。
- 生成或修改 HTML：读 [阅读界面](references/html-experience.md)。只写 Markdown 时无需此文件。
- 校准“足够详细”或深化已有教程：读 [示范与反例](references/exemplar.md)。
- 交付前：读 [验收标准](references/acceptance.md)。
- 用 [课程工作表](assets/course-worksheet.md) 建立唯一规划记录，不另建重复大纲。
- 工具的提取、严格验收与发布命令：见 [证据与实验](references/source-and-labs.md)；只写概念文档时不加载工具步骤。

## 教学契约

1. 从用户动作出发，追踪输入、处理、输出、ID、存储、分支和失败。不要按目录逐文件介绍。
2. 每个重要机制讲清：为什么需要 → 如何工作 → 数据怎样改变 → 源码在哪里 → 如何操作 → 看什么结果 → 出错从哪查。
3. 图、代码和正文互相补充，不用流程图替换有效解释，不用卡片代替完整推导。
4. 原始源码逐字摘录，给版本、文件、函数和行号；简化代码单独标注。没访问到源码时明确降为原理教程，不虚构调用路径。
5. 核心执行链提供完整函数精读，说明参数、状态、调用、返回、异常和副作用。巨型产品函数可用连续片段配调用图，另以教学实现展示完整最小函数。
6. 明确内容身份：源码事实、教学简化、模拟演示、扩展设计。测试状态另列“已实测 / 未实测”。
7. 用户指定必需的组件须进入正文、配置、实验和验收，不能悄悄降为可选；新项目也不能自动增加 Neo4j 或双向量库。
8. 继承已授权范围直接完成；只问影响正确交付的缺失信息，不强制每章审批，也不自动部署、发布或产生外部写入。

## 工作顺序

### 1. 锁定目标与事实基准

记录受众、学完能做的动作、系统环境、语言、必需组件、源码提交、工作区变化、镜像版本、交付形式与运行条件。已有课程先读构建源文件与验收记录，保留用户要求保留的正文与锚点。

读取项目约束，从路由/CLI/任务入口追踪主线。先确定“准备数据”和“使用数据”两条链；非 RAG 项目替换为对应生产/消费链。建立证据表：业务动作 → 入口 → 关键函数 → 输入输出 → 持久化 → 条件/错误 → 证据位置。

### 2. 建立学习依赖与贯穿案例

采用“全貌 → 首次成功 → 数据准备 → 核心存储/计算 → 请求执行 → 结果形成 → 增强机制 → 复现评测 → 运行观测”的默认路线，按项目调整。学习顺序不必等于文件顺序；章内执行顺序须与源码相符。

选一组明确虚构或获准使用的资料贯穿全课，设置稳定身份、版本与出处。包含正常、缺失、冲突/歧义、失败降级场景。不要每章重新换例子。

### 3. 做深一章，建立写法

先将一个核心机制写到可手算或追踪数据、再运行验证的程度。填齐工作表中的问题、前置知识、输入输出、步骤、完整函数、实验与判读、反例和练习。用示范文件检查是否仍停留在定义与命令清单。

详细课程可参考每章 8–12 个实质小节、约 3,000–5,500 汉字正文；复杂核心章可更多。这是本案例的深度参考，不是通用硬指标。正文统计排除代码、导航、术语与重复文字。深度靠因果与证据，不能凑字数。

### 4. 完成全课程与实验

按学习依赖逐章完成，不把后半程写成提纲。先建立原理和中间产物，再映射产品源码，再连接可运行教学实现。有双语言要求时，两套实现共享协议、输入、排序和失败语义，均可独立运行，不能只翻译几段语法。

增强章回答基础方案哪里不足、如何补充、何时失效、如何做开关对照。观测章在全链路之后解释父子上下文、异步边界、流结束和真实覆盖范围；模拟树不能被说成真实服务记录。

### 5. 生成阅读产物

内容、样式、交互、生成器分开维护；按用户要求产出自包含 HTML 或文档。用 `scripts/extract_source.py` 唯一定位并提取源码，记录固定提交或工作区身份、行号与哈希，再把输出交给构建器。用可用绘图工具；缺 Archify 时使用本地 SVG 等完成，不能因此省略图示。

### 6. 验收与交付

执行结构检查、摘录核验、关键实验、交互检查和人工教学审查。源码课程运行 `scripts/audit_course.py --require-revision`，零摘录默认失败；只有明确交付概念教程时才可加 `--allow-no-source`，并保留未核验警告。静态工具不判断语义与教学质量。

新章须更新导航、分母、上下章、恢复阅读和打印。已有浏览器只改 hash 可能继续显示旧文档；实际重新加载或用带构建版本的 URL，核实目录和正文。保留既有学习记录，不清空存储来修复章节数。

交付准确入口、覆盖范围、实测结果和未实测边界。检查成功不是“全部服务已运行”，trace ID 不是“平台已接收”，引用编号不是“结论获证据支持”。

## 深化已有课程

先列缺口：原理、数据变化、调用连接、操作、预期输出、失败判读或证据。逐项补齐，保持有效正文，增加小节目录和展开面板。不要删掉用户认可的源码导读，也不要把“更详细”理解成增加组件名单与装饰动画。
